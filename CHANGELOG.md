# Changelog

All notable changes to this fork of Buttercup Desktop are documented here.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and this project aims to adhere to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

Release history up to and including **2.28.1** predates this file and lives in the [git tags](https://github.com/codekunde/buttercup-desktop/tags) and the original project's GitHub Releases.

## [Unreleased]

### Added

- Long notes no longer fill the whole entry pane. A note field shows about 10 lines, with **Show more** / **Show less** to expand it; the button only appears when the note is longer than that. A long string without spaces (such as a key) wraps inside the pane instead of running off to the right. While editing, the note box grows up to 10 lines and then scrolls.
- Restore a damaged vault from its last saved copy (follow-up to upstream [#1233](https://github.com/buttercup/buttercup-desktop/issues/1233)): when a vault file is incomplete or damaged, Buttercup offers to write back the copy it keeps from the last time the vault was opened or saved on this computer. Your password is checked against that copy first. A damaged local file is kept in the vault's backup folder before it is replaced. Changes saved on other devices after that copy are missing, and the dialog says so.
- Change a vault's master password in **Vault Settings → Password** (the vault must be unlocked): type the current password and the new one twice. Before changing it, Buttercup saves a backup of the vault, still locked with the current password, in the vault's backup folder (also when local backups are off) and shows where. If biometric unlock is set up for the vault, it gets the new password too. Every other app or device that opens the vault needs the new password afterwards (upstream [#1046](https://github.com/buttercup/buttercup-desktop/issues/1046)).
- **Upload Vault** for Google Drive: when adding a Google Drive vault, upload a `.bcup` file from your computer into the folder you're in, and it's selected straight away. Buttercup only has access to Drive files it created itself, so a vault made by another app, uploaded in the browser, or created by the original Buttercup (which used a different Google sign-in) didn't show up in the list (upstream [#1388](https://github.com/buttercup/buttercup-desktop/issues/1388), [#1309](https://github.com/buttercup/buttercup-desktop/issues/1309)). The upload is a copy: other devices should switch to the new file.
- Releases come with a `SHA256SUMS.txt` for all installers and a `build-info-<os>.txt` per platform (commit, Node, npm, Electron and electron-builder versions), and the README explains how to verify a download. CI and release builds use the Node version pinned in `.nvmrc`. Builds are not byte-for-byte reproducible; the README says so (upstream [#1193](https://github.com/buttercup/buttercup-desktop/issues/1193)).
- Vaults lock when you lock the screen or the computer goes to sleep (upstream [#1160](https://github.com/buttercup/buttercup-desktop/issues/1160)). On by default, also for existing installs; turn it off in **Preferences → Security → Lock vaults when the computer locks**. On Linux, Electron only reports sleep, so there it locks on sleep but not on a screen lock.
- A `.deb` package for Debian, Ubuntu and derivatives, for x64 and arm64 (`Buttercup-linux-amd64.deb`, `Buttercup-linux-arm64.deb`), next to the AppImage. Install it with `sudo apt install ./Buttercup-linux-amd64.deb`. Unlike the AppImage it doesn't update itself: install each new release's `.deb` over the old one.
- Select several entries at once: **Ctrl/Cmd+click** adds or removes an entry, **Shift+click** selects a range. Right-click one of them to move them all to another group or to the Trash. Esc, a plain click or the arrow keys clear the selection (upstream buttercup/ui#25).
- Import from **KeePassXC (CSV)** (KeePassXC: Database → Export → CSV File): keeps the group tree, notes and TOTP codes. And from **1Password (1PUX)**, the export format of 1Password 8 (and 1Password 7 on Windows and Mac), which no longer export `.1pif`: one group per 1Password vault, logins with all their URLs, cards, secure notes, SSH keys, custom fields, TOTP codes, notes and tags. Attachments aren't imported. Both are in **Current Vault → Import** (importer fork, upstream buttercup-importer [#61](https://github.com/buttercup/buttercup-importer/issues/61) and [#58](https://github.com/buttercup/buttercup-importer/issues/58)).
- A "Scan QR code" button next to an entry's OTP field, for sites that only offer a QR code during 2FA setup with no manual-entry fallback. It reads an image from the clipboard (screenshot the QR, then click scan) or, if the clipboard has no image, opens a file picker. Resolves upstream [#1042](https://github.com/buttercup/buttercup-desktop/issues/1042).

### Changed

- Updates are manual for now: when a new version is out, the update dialog shows what's new and its **Download** button opens the releases page. The app no longer downloads or installs an update itself, because releases aren't code-signed and the app couldn't check who built one. The update check and the repository links now point at `buttercup-fork/buttercup-desktop`.
- The app ID is now `net.codekunde.buttercup` instead of the original project's `pw.buttercup.desktop`, so this fork no longer shares an install identity (Windows installer and taskbar ID, macOS bundle ID) or keychain entries with an installed upstream Buttercup. An earlier test build of this fork installs alongside the new one instead of being upgraded: uninstall it by hand. On macOS, Touch ID unlock has to be turned on again once per vault. Vaults, settings and the vault list are not affected.
- Browsing a large Google Drive when adding a vault is much faster: the Google Drive client no longer scans every file once per folder (upstream googledrive-client #4). On a drive with 30,000 items, opening a folder goes from about 7 seconds to well under a second. The Google Drive client is now at `e91dfc3`.
- Word passwords from the password generator are stronger: words now come from an 8,192-word list instead of a 1,700-word one, so the default 4 words give about 52 bits instead of 43. The generator is now at `f594e3a`.
- Refreshed the file vault icon shown in the **Add Vault** menu and on file vault tabs.
- The README's Google Drive notice said sign-in doesn't complete, which stopped being true with the new sign-in. It now describes the real limit: while the fork's Google sign-in app is in Testing mode, only test users can sign in, and they sign in again every 7 days.
- New installs clear the clipboard 30 seconds after a copy (was: never). Existing installs keep the setting they have. The setting now explains that clipboard history tools (Win+V, Flycut, Maccy, Klipper…) keep their own copy that Buttercup can't clear, and the README's Precautions say how to avoid that (upstream [#1158](https://github.com/buttercup/buttercup-desktop/issues/1158)).
- An entry's field buttons (copy, show password, history) are always visible now, slightly muted, instead of appearing only on hover: easier to find, and usable on touchscreens and with the keyboard (they brighten on hover and on keyboard focus). Empty fields still show none (upstream buttercup/ui#52).
- New application icon and artwork: the padlock badge for the app, tray/taskbar and file icons, the local-file, Dropbox, Google, Google Drive and WebDAV vault icons, the macOS tray template and Linux tray icons, and a recoloured DMG background.
- Rewrote the README to match the fork as it is today: fixed the configuration, vault-storage and offline-cache paths (the folder is `Buttercup-nodejs`), documented the Apple Silicon and Linux arm64 builds and the real release assets and pipeline, corrected the `npm audit` statement, added the Google Drive sign-in known issue, and dropped the upstream project-closure notice, Keybase badge and Arch AUR section. The badges now show this fork and its latest release.
- Building from source now requires Node.js 22 or newer (was 20), matching the core library. CI already built on 22.
- Google Drive sign-in no longer goes through the original project's `buttercup.pw` website, which is offline. Google now redirects straight back to the app on a short-lived local address (`http://127.0.0.1:<port>`, Google's recommended flow for desktop apps), with a random `state` value checked on the way back. The auth code is read as a normal URL parameter, so the extra `iss` parameter Google now sends no longer breaks it. The unused `buttercup://auth/google` link handler is gone, so a web page can no longer hand the app a sign-in code. The app now uses this fork's own Google OAuth client, so Google Drive vaults added before this version ask to sign in once more. While that client is in Google's Testing mode, only accounts added as test users can sign in, and they have to sign in again every 7 days; the README known issue stays until it is published.
- The app no longer depends on the deprecated `@buttercup/ui` library, which upstream archived in 2024. Its components were already copied into the app; the last four imports (vault tabs, the search result icon, drag-and-drop and the vault theme) now use the app's own copies. Packages the vault UI had only been getting through `@buttercup/ui` (`otpauth`, `react-textarea-autosize`, `react-popover`, `@buttercup/react-formatted-input`, the Inter font and others) are now direct dependencies, at the versions already in use.

### Fixed

- Starting Buttercup a second time (eg. opening a `codekunde-buttercup://` link while it runs) no longer starts a second copy's start-up before it quits. The second process is refused the single-instance lock and now quits right away, instead of also setting itself up next to the running one.
- Right-click a field in an entry to copy it, the same as its clipboard button (upstream [#773](https://github.com/buttercup/buttercup-desktop/issues/773)). Text boxes get a right-click menu with Undo, Cut, Copy, Paste and Select All, and selected text can be copied the same way.
- **Current Vault → Import**, **Export**, **Lock** and **Biometrics** right after switching vaults could act on the previous vault: the menu is rebuilt a moment after the switch, and its items used the vault it was built for. They now act on the vault that is current when you click.
- More sites show their icon in the entry list (upstream [#1071](https://github.com/buttercup/buttercup-desktop/issues/1071)). Buttercup only tried `https://<site>/favicon.ico`, so sites that declare their icon in the page (`<link rel="icon">`, often a PNG or SVG elsewhere) kept the placeholder. It now reads the site's home page for its icon, and falls back to `/favicon.ico`, also on the site it redirects to (eg. `www.`). Icons still come only from the entry's own site (or where it points for its icon), without cookies and only over https, and are kept for two weeks in Buttercup's cache folder; a site without an icon is asked again after two days.
- A field's history no longer lists its current value as a "previous value". It happened when a field was saved again with the same value, for example right after creating an entry (core fix: setting a field to the value it already has no longer adds history).
- Changing the type of a field that already had one (for example Note to Password) is kept now. It was undone on save, so only a field's first change from Text stuck (upstream [#1218](https://github.com/buttercup/buttercup-desktop/issues/1218), fixed in core #12). Renaming or deleting a field also no longer leaves its type behind, where a new field of the same name would pick it up.
- A new custom field opens its name for typing, an unnamed field is highlighted, and the reason Save is disabled ("Give every custom field a name to save") is shown next to the buttons. It was only in the tooltip of the disabled Save button, which often doesn't show, so adding a custom field looked like it broke saving (upstream [#1394](https://github.com/buttercup/buttercup-desktop/issues/1394)).
- A vault file that was cut off while being saved (for example when the computer lost power, or a sync service copied it halfway) now gets a clear message when you unlock it: the file is incomplete or damaged, and where to restore it from. Before, it said "Failed deriving key: Salt must be provided" (upstream [#1233](https://github.com/buttercup/buttercup-desktop/issues/1233)). The cause, saving the file in place, is fixed in the core library.
- The portable Windows app now keeps all its data (vault list, settings, backups, log and the app's own profile) in a **Buttercup-data** folder next to the `.exe`, instead of in your user folder (`AppDataRoamingButtercup` and `Buttercup-nodejs`). On its first start it copies the vault list and settings from there, so your vaults are still listed; the originals are left in place. Setting `BUTTERCUP_HOME_DIR` now moves the app's profile too (upstream [#1254](https://github.com/buttercup/buttercup-desktop/issues/1254), [#1072](https://github.com/buttercup/buttercup-desktop/issues/1072)).
- Locking a vault from the browser extension no longer leaves it in an "invalid state" that only a restart fixed (upstream [#1317](https://github.com/buttercup/buttercup-desktop/issues/1317)): two locks at the same time, for example from the extension while the app also locked it, broke the vault (fixed in core #13). A lock from the extension also saves unsaved changes first, like an automatic lock, and says so if they couldn't be saved; before, it dropped them without asking.
- Changes that couldn't be saved (the vault's file or server was unreachable, or a save was still running) are no longer thrown away silently. Quitting or locking a vault by hand now asks first: **Save and Quit/Lock** tries again and only goes ahead if that works, **Quit/Lock Anyway** discards the changes, **Cancel** keeps everything open. When a vault locks by itself (idle timer, screen lock, sleep), Buttercup tries one more save, then locks anyway and tells you if changes were lost (upstream [#1230](https://github.com/buttercup/buttercup-desktop/issues/1230)).
- A vault whose server stopped answering in the middle of a save (eg. a WebDAV or cloud connection that stalled after waking from sleep) could no longer be locked: **Lock Anyway**, auto-lock and closing the window all waited for that save, for good. Locking now waits 5 seconds at most for a running save or update, then locks anyway; the stuck save is dropped, with its unsaved changes, as **Lock Anyway** already said. The vault can be unlocked again straight away. Needs `buttercup-core` `c999a02` (`lock({ force: true })`).
- Adding a custom field with a name the entry already uses (for example a second `username`) no longer erases the other field's value on save. The clashing name is now marked in red and **Save** stays disabled until you rename or remove the field (upstream [#1159](https://github.com/buttercup/buttercup-desktop/issues/1159)).
- Removing a vault whose settings were never changed no longer writes an error to the log (`Failed removing vault settings … ENOENT`). There was no settings file to delete; the vault was removed either way.
- The same vault can no longer be added twice: it showed up in two tabs, and creating a **new** vault on a file already in the list replaced that vault. Buttercup now says the vault is already there and under which name (local files, WebDAV and Google Drive; vaults added earlier are recognised once unlocked) (upstream [#1172](https://github.com/buttercup/buttercup-desktop/issues/1172)). Vault names in the unsaved-changes dialogs no longer show `&` as `&amp;`.
- No more "Update failed: 404" message every 30 minutes when the release page can't be found (no releases published yet, or GitHub answering 404 as it does while the fork's account is suspended). The log notes it once per run instead. Real update failures still show the message.
- WebDAV and Dropbox: on Windows, a new vault created in a subfolder ended up as one file named `folder\name.bcup` at the server root, because paths were joined with backslashes. New WebDAV file and folder names with accents are now saved in the composed Unicode form (NFC) that most servers expect (upstream buttercup-mobile [#90](https://github.com/buttercup/buttercup-mobile/issues/90)). Both come from the CodeKunde `file-interface` fork, which the app now uses.
- The bench illustration on the add-vault and locked-vault screens: the person's trousers had lost their colour and blended into the background.
- Large vaults were slow to edit and import: after every change the core library rebuilt its whole list of groups, entries and tags, so each change took longer the bigger the vault. It now only updates what changed: adding 1,000 entries went from about 22 seconds to a fraction of a second (core fork #8).
- Editing a big vault was still slow, and Ctrl+F could take seconds to open while a save ran: to find an entry's group, the core library searched every entry in the vault, once for every entry. On a 5,000-entry vault, applying and saving one edit went from about 14 seconds to about 2, and Ctrl+F during a save opens in about a third of a second instead of over 2 seconds (core fork #9).
- Local vault files are no longer left half-written when a save is interrupted (the computer loses power, the app is killed, or a sync service copies the file mid-save). Such a vault no longer unlocked ("Failed deriving key: Salt must be provided"). The core library now writes a temporary file next to the vault and swaps it in only once it is complete (upstream [#1233](https://github.com/buttercup/buttercup-desktop/issues/1233)).
- The Trash counter stayed at 0 when entries were moved to the Trash: it only counted entries inside groups in the Trash, and counted those in nested groups more than once.
- Entry icons showed only the generic placeholder: they came from upstream's icon service (`icon.buttercup.pw`), which is offline. Icons are now loaded straight from each entry's own site (`https://<site>/favicon.ico`), so no third party learns which sites a vault holds logins for. Sites without a favicon at that address keep the placeholder; the "show site icons" preference still turns them off. Also fixed the host-name lookup behind the icons, which kept the port and, for URLs saved without `https://`, the whole path.
- Exporting a vault to Buttercup CSV and importing it again lost data: every entry came back as a login, a website's URL showed up as a custom `url` field, and field types (multi-line, OTP), field order and tags were dropped. Exports now include each entry's type and attributes (two new columns), and the Buttercup CSV import restores them; CSVs exported by older versions still import as before. Desktop now uses the CodeKunde fork of `@buttercup/exporter` (upstream buttercup/buttercup-importer#64, #60).
- Importing from other password managers picks up the importer fixes: Bitwarden exports in the current format (cards, identities, SSH keys, secure notes, custom fields and collections) no longer fail or lose data, and encrypted Bitwarden exports get a clear error; 1Password for Windows `.1pif` files import; CSV files with backslash-escaped or stray quotes (as 1Password writes them) parse; and LastPass notes keep their line breaks.
- The "Copied!" confirmation toast sometimes stayed on screen until its "X" was clicked. This happened when a second copy arrived just as the previous toast was fading out; each copy now gets its own toast.
- The updater's error toast showed the raw network/HTTP error text (e.g. a full GitHub 404 message), which could grow large enough to dominate the screen. It now shows a short summary ("GitHub is currently unavailable", or a generic message otherwise) with a "Details" button that opens a dialog with the full error, for anyone who wants it.
- Vault saves weren't debounced: every single edit (effectively every keystroke) fired its own save immediately, so fast edits could send overlapping saves racing each other. Saves are now double-edged debounced per vault - the first save still starts immediately, but further edits made while it's in flight are coalesced into one trailing save with the latest state, instead of firing one save per edit (buttercup/buttercup-core#182).
- Saving to Google Drive could fail or corrupt the upload when a vault or attachment name contained non-ASCII characters (e.g. `café.bcup`, `日記.bcup`): the upload's `Content-Length` counted characters instead of bytes. Fixed in the `googledrive-client` fork, which the app now installs from instead of npm.
- Switching vault tabs briefly flashed a bright line under the tab being left. The selected tab dropped its bottom border, and the tab animation then grew it back from the browser's default (3px, in the text colour). The selected tab now keeps a transparent border, so only the colour fades.
- Adding a vault while other vaults were open left you on the previously active tab, or on the first tab if you had just removed the active vault. The app now switches to the vault you just added.
- Linux: the AppImage kept showing "Uncaught Exception: Error: write EPIPE" once the terminal or launcher that started it had gone away. Every log line is also written to the console, and writing to a closed console crashed. Those writes are now dropped; the log file still gets every line (upstream [#1330](https://github.com/buttercup/buttercup-desktop/issues/1330)).
- Adding an entry right after switching to another vault (for example the vault you just added) could fail with "Vault failed to save: … Cannot read properties of null (reading 'createEntry')". The group selected in the previous vault stayed selected, and the new entry was put in a group the vault doesn't have. The app now selects the vault's first group instead. Restarting the app worked around it.
- Google Drive: when Google refused to renew the sign-in with anything other than a plain "expired" answer, the vault wouldn't open ("Failed fetching Google Drive vault: Bad refresh response"). It now asks you to sign in to Google again, and the log records Google's answer (upstream [#1391](https://github.com/buttercup/buttercup-desktop/issues/1391)).
- Turning off **Start with session** in Preferences now really stops Buttercup starting at login on Windows. Once on, it couldn't be turned off again: the app didn't recognise its own login item, so it never removed it. The portable app now registers its `.exe` instead of the temporary folder it runs from (upstream [#1267](https://github.com/buttercup/buttercup-desktop/issues/1267)).
- Windows: when an update can't start its installer (for example Windows or a virus scanner blocks it, which is more likely while the installer isn't code-signed), Buttercup no longer just closes without updating. It stays open, says the update couldn't be installed, and offers to open the download page so you can run the installer yourself (upstream [#690](https://github.com/buttercup/buttercup-desktop/issues/690)).
- A new entry is selected once it's saved, instead of leaving "No document selected", and clicking it before its save had finished no longer selects nothing: a new entry only gets its ID when the main process has saved it.
- In a narrow details pane, a field's label now goes above its value. Beside it, the value was left a few letters wide and split letter by letter, with a sideways scrollbar (upstream [#1329](https://github.com/buttercup/buttercup-desktop/issues/1329)). Password dots stay on one line.
- Field history: the time column is now "Set" (when that value was set, it said "Created"), and shows "Not recorded" for Format A vaults, which don't store it, instead of staying empty (upstream [#1145](https://github.com/buttercup/buttercup-desktop/issues/1145)). The history button says "No previous values" when it's disabled.
- Release notes in the update dialog have readable line spacing and scroll when long (upstream [#1016](https://github.com/buttercup/buttercup-desktop/issues/1016)).
- Untranslated English text can now be translated (upstream [#1275](https://github.com/buttercup/buttercup-desktop/issues/1275)): the password generator, the field history dialog, attachment details, "Not set.", "Empty" and "No username" in the entries list, the format upgrade confirmation, the link tooltip and the OTP error. An OTP that can't be read now shows "ERROR" instead of the raw error text.
- Closing the window to the notification area right after moving or resizing it no longer shows "Object has been destroyed", and the window opens again where you left it (upstream [#688](https://github.com/buttercup/buttercup-desktop/issues/688)). Its new position was saved 750 ms after the last move, by then the window was gone; closing now saves it right away.
- Clicking a new entry right after saving it keeps the keyboard in the entries list: copying the username or password with Ctrl/Cmd+B and Ctrl/Cmd+C and moving with the arrow keys work straight away. Before, if the click came before the save had finished, the list lost the focus when the save finished and the shortcuts did nothing until you clicked again.
- **Load Existing** and Google Drive's **Upload Vault** can open a vault file with another extension, or none: the file dialog now also offers **All Files** (upstream [#1371](https://github.com/buttercup/buttercup-desktop/issues/1371)). A file that isn't a Buttercup vault is turned away with a message that says so, instead of "Failed unlocking source: No valid signature in vault".
- The CSV export opens in Excel with accented characters intact: it now starts with a UTF-8 BOM, which tells Excel the file is UTF-8. Before, Excel read it in the local code page, so "Accès" showed as "AccÃ¨s" (upstream [#749](https://github.com/buttercup/buttercup-desktop/issues/749)). The importer skips the BOM, so these exports still import, and so do CSV files Excel saved as "CSV UTF-8". The duplicate `!group_id`/`!group_name` columns from that report were already gone with the exporter update behind the export round-trip fix above.
- Exporting a vault to CSV failed for the whole vault when any entry had a field named like a built-in object property, such as `toString` or `constructor`. Entries without that field read the built-in function instead of an empty value. The export now comes from exporter `a98ef49`.
- Importing a Buttercup CSV export dropped fields named `constructor` or `prototype`, so such a field was lost on export and re-import. They now import like any other field (only `__proto__` is still skipped). The import now comes from importer `5e576eb`.
- A field's history (**Previous Value**) listed the field's current value as a previous one after a save that merged changes from another device (eg. a vault shared through a sync service). Merges now keep only the values that really came before. A field that was deleted and added again also keeps that deletion in its history in the newer vault format. Needs `buttercup-core` `f26e7ff`.

### Security

- On Linux, vaults now lock when the screen locks, if **Lock vaults when the computer locks** is on (upstream [#1160](https://github.com/buttercup/buttercup-desktop/issues/1160)). Before, that setting only worked on Windows and macOS. It listens for the screen saver's lock signal on D-Bus (GNOME, KDE, Cinnamon, MATE, Xfce) through the system's `dbus-monitor`, which comes with the `dbus-bin` package; without it a warning is logged and only sleep locks the vaults.
- Updated `proxy-addr` (a web-server library inside the Secure File Host) to 2.0.8, which fixes a critical IP-spoofing advisory (GHSA-jqcg-44mw-7w3h). The Secure File Host doesn't use `trust proxy`, so it wasn't exploitable here.
- Update release notes are cleaned before they are shown, and the release name is shown as plain text. Before, HTML in a release (scripts, event handlers, `javascript:` links) would have run inside the app window, which has full access to the computer. Only text formatting and http(s)/mailto links are kept.
- The app window now has a Content Security Policy: no inline or remote scripts, no plugins or frames. Connections to web servers stay allowed, because the Dropbox, Google Drive and WebDAV pages make their requests from the window. To make that possible, `otpauth` (one-time passwords) is updated to 9.x; 7.x used `eval`.
- On Windows, anything copied from a vault (passwords, usernames, other fields) is marked confidential, so Windows clipboard history (Win+V) and cloud clipboard sync no longer keep it. Pasting works as before, and auto-clear still clears it. This uses a small native module in this repo (`native/conceal-clipboard`), because Electron can't write those clipboard markers itself. On macOS and Linux, copies work as before for now.
- Updated to the current core library fork: its dependency and security updates, and all storage requests (Dropbox, Google Drive, OneDrive, WebDAV) through the built-in `fetch` instead of `node-fetch`. The app's own Dropbox client and `@buttercup/fetch` now also come from the CodeKunde forks, and the Google Drive client is on the fork's current version, so `node-fetch` is no longer used anywhere (it stays installed only because `webdav` and `@buttercup/google-oauth2-client` still list it).
- The vault importer now comes from the CodeKunde `buttercup-importer` fork, which fixes two prototype-pollution advisories in how it reads imported files: `csv-parse` (GHSA-8cw4-87c7-c6xx; CSV, Buttercup CSV and LastPass imports) and `xml2js` (GHSA-776f-qx25-q3cc; KeePass XML imports). `npm audit` is now clean.
- The app window can no longer be navigated away from Buttercup's own page (upstream [#1238](https://github.com/buttercup/buttercup-desktop/issues/1238)). The window has full system access, so a web page or local file loaded in it (a dropped link, a redirect) could have run code on your computer; such navigations are now blocked, and web links open in your browser instead. Links handed to the operating system are limited to `http`, `https` and `mailto`: Ctrl/Cmd+clicking an entry URL like `file:///…/program.exe` or `smb://…` no longer opens it. An entry URL saved without a scheme (`github.com`) now opens as `https://github.com` on Ctrl/Cmd+click; before, it went nowhere.
- Release builds no longer include the developer tools (upstream [#712](https://github.com/buttercup/buttercup-desktop/issues/712)). Ctrl+Shift+I and the Debug menu opened a console with full access to the unlocked vaults to anyone at the keyboard. The View menu in release builds now only has zoom and full screen (no Reload either); development builds (`npm start`) keep both menus.
- Release builds refuse to start with Chromium's `--remote-debugging-port` or `--remote-debugging-pipe` switch, which would have opened a debugging console with access to the unlocked vaults (Electron has no fuse for these; `--inspect` was already blocked).
- Linux: the AppImage writes a warning to the log when it runs without Chromium's sandbox. Its launcher turns the sandbox off by itself on systems that block unprivileged user namespaces, such as Ubuntu 24.04 and later, so the app starts instead of failing with a sandbox error (upstream [#1355](https://github.com/buttercup/buttercup-desktop/issues/1355)). The README now explains this and recommends the `.deb` there, which installs an AppArmor profile and keeps the sandbox.
- Generated passwords are no longer biased. The password generator now comes from the CodeKunde `buttercup-generator` fork. Before, the last character of every set (`Z`, `z`, `9`, `-` and the last symbol) and the last word of the word list could never come out, and the character sets weren't picked as often as their weights say: `_-` came out about 2% of the time instead of 7%. Random numbers now come from the system's secure random source (`crypto.getRandomValues`), with every value equally likely.

## [2.31.0] - 2026-09-10

A pass over the open upstream issue tracker: 17 issues fixed or confirmed resolved, plus keyboard and preferences polish. The macOS build now ships separate Intel and Apple Silicon artifacts, and the in-app updater points at this fork.

### Added

- Ctrl/Cmd+Tab and Ctrl/Cmd+Shift+Tab now cycle forward and backward through the vault tabs (Ctrl/Cmd+PageDown / +PageUp do the same).
- Copying a field now shows a brief confirmation toast. The message names what was copied: "Username copied!" / "Password copied!" from the entries-list keyboard shortcuts (Ctrl/Cmd+B, Ctrl/Cmd+C), and "OTP copied!" / "Password copied!" / "Username copied!" / "{field name} copied!" from a field's clipboard button, falling back to "Copied!". The history-dialog copy button shows "Copied!". The toast is sized to its text rather than Blueprint's default 300px minimum. The entry-detail and history copy buttons also now use the native clipboard API instead of the hidden-`textarea` `execCommand` hack, matching the entries-list shortcuts.

### Changed

- The in-app auto-updater now checks this fork's releases (`codekunde/buttercup-desktop`) instead of the archived upstream repo. It had still been pointing at `buttercup/buttercup-desktop`, so it would never have found a fork release - and could have tried to "update" an installed fork build back to an upstream one.
- The "Clear clipboard after" and "Lock vaults after" settings (Preferences → Security) are now dropdowns with sensible presets (Off, 30 seconds, 1 minute, … up to 1 day) instead of continuous sliders. The lock-vaults slider spanned 0-24h with a tick label every hour, so the labels were an unreadable smear and small values were almost impossible to select with the mouse. A previously-saved value that isn't a preset stays selectable.
- macOS builds are now produced for both Intel (`x64`) and Apple Silicon (`arm64`), as separate `.dmg` / `.zip` artifacts named with the architecture (upstream [#1276](https://github.com/buttercup/buttercup-desktop/issues/1276)). The previous build was Intel-only, so on Apple Silicon it ran under Rosetta 2 - which is slow (the likely cause of the "everything lags ~1 second" reports) and which recent macOS flags with a "will not open in a future release of macOS" warning. Apple Silicon users should now install the `arm64` build.

### Fixed

- Auto-lock (Preferences → "Lock vaults after…") works again (upstream [#1033](https://github.com/buttercup/buttercup-desktop/issues/1033)). It was gated on an internal flag that defaulted to off and was only flipped on as a side effect of the "pause auto-update while editing" logic, and the timer was only ever (re)started by mouse movement in the window - so in most cases it never armed. Auto-lock is now driven directly by the preference: the timer is armed when a vault is unlocked, when the preference changes, and on any mouse **or keyboard** activity, and it's suspended only while you're editing an entry (so you can't be locked out mid-edit; leaving the editor always clears that suspension).
- You can now connect vaults from more than one Dropbox account (upstream [#1314](https://github.com/buttercup/buttercup-desktop/issues/1314)). The Dropbox sign-in window ran in the app's shared session, so after the first account was connected it silently reused that login with no way to switch. It now uses a fresh, throwaway session each time, so Dropbox always asks which account to use; the session is wiped when the window closes.
- Signing in to Dropbox with a Google account is more likely to work (upstream [#888](https://github.com/buttercup/buttercup-desktop/issues/888)). The sign-in window now presents a normal desktop Chrome user-agent instead of the default one containing "Electron", which Google rejects with "this browser or app may not be secure". This is a mitigation - Google may still block the embedded window; the robust fix is an external-browser sign-in flow (tracked separately).
- Unlocking a vault from the tray icon or the Vaults menu no longer shows a blank password dialog (upstream [#1280](https://github.com/buttercup/buttercup-desktop/issues/1280)). The prompt worked out which vault it was for from `VAULTS_STATE.currentVault`, which is only set by clicking a vault tab - so a menu/tray unlock left it unset and the dialog rendered with no password field. The unlock flow now records the target vault explicitly, and navigating to a vault via the menu/tray also keeps the rest of the app (facade refresh, attachments) pointed at it.
- After unlocking a vault, the first group is now selected automatically, so the entries pane is populated and the "New Entry" button works straight away instead of staying disabled until a group is clicked (upstream [#1045](https://github.com/buttercup/buttercup-desktop/issues/1045)). The underlying crash ("No group selected") was already guarded; this removes the dead-end state that led to it.
- The entries list filter now works again (upstream [#1111](https://github.com/buttercup/buttercup-desktop/issues/1111)). Two bugs stacked on top of each other: (1) choosing "Filter" from the sort menu showed nothing - a JSX condition with mixed `&&`/`||` and missing parentheses evaluated to the bare value `true` (which React renders as nothing), so the header went blank with no input box; (2) once the box did appear, the first keystroke crashed the whole window with "Searching interface not prepared", because the filter created a `VaultFacadeEntrySearch` and called `searchByTerm` without ever awaiting its async `prepare()`. The filter is now a plain synchronous, case-insensitive, all-tokens-must-match substring match over each entry's visible field values, which also can't be tripped up by a null field value from a rough import.
- Moving an entry to the trash while editing it now closes the editor instead of leaving it open on a stale copy (with the save / cancel / trash bar still showing). The "stop editing when the edited entry is trashed" check was reading a stale snapshot of the editing state because of an incomplete `useCallback` dependency list.
- A vault save that stalls indefinitely (e.g. a WebDAV or cloud server that accepts the connection but never responds) no longer leaves every button disabled until the app is restarted (upstream [#1077](https://github.com/buttercup/buttercup-desktop/issues/1077)). The save now times out after 90 seconds, clears the saving state and shows a "Vault failed to save: timed out" error instead of hanging forever. If the underlying request does eventually complete after the timeout, that outcome is logged rather than surfaced.
- Linux: the custom URL scheme (`codekunde-buttercup://`) is now registered at runtime when running from a bare AppImage, so Google Drive and other protocol auth callbacks are delivered back to the app without requiring AppImageLauncher (upstream [#987](https://github.com/buttercup/buttercup-desktop/issues/987)). A `~/.local/share/applications/codekunde-buttercup.desktop` entry is written/refreshed on start and registered via `xdg-mime`.
- A protocol URL passed on the command line at cold start (Linux/Windows) is now handled once the window is ready, instead of only being handled when an instance is already running.
- Confirmed already resolved in this fork's V2 codebase / Electron 44 base, and closed off: exporting a vault as CSV no longer shows an endless list of disabled menu items (upstream [#670](https://github.com/buttercup/buttercup-desktop/issues/670) - export is now a single menu item; verified by code inspection, not yet re-tested on macOS), emptying the trash no longer throws (upstream [#668](https://github.com/buttercup/buttercup-desktop/issues/668)), and the app launches with Windows Defender "Mandatory ASLR" forced on (upstream [#502](https://github.com/buttercup/buttercup-desktop/issues/502)).
- The entries-list copy shortcuts (Ctrl/Cmd+C for password, Ctrl/Cmd+B for username) now always act on the currently selected entry rather than the previously selected one (upstream [#1384](https://github.com/buttercup/buttercup-desktop/issues/1384)). The handlers now read live selection state through a ref, working around `react-hotkeys` caching stale handler closures, and look the field up by property (`username` / `password`) instead of by its display title.
- The entries-list copy shortcuts now write to the clipboard via the native clipboard API instead of a hidden-`textarea` `execCommand` hack. The hack stole and then dropped keyboard focus, which left the list unfocused so the next shortcut press was silently ignored (and beeped). Copying via shortcut now also arms the auto-clear-clipboard timer, matching the field copy buttons.
- Keyboard navigation of the entries list is now consistent: arrow keys move the highlight and keep DOM focus on the highlighted row (previously focus lagged one row behind), and Enter acts on the highlighted entry instead of clicking whatever element happened to hold focus - which had been snapping the selection back to a previously focused entry.
- Enter now activates the primary action from the keyboard where it previously did nothing (upstream [#1349](https://github.com/buttercup/buttercup-desktop/issues/1349)): the "unlock" button on a locked vault (Enter or Space), the password field when adding or creating a vault, and the WebDAV URL / password fields in the add-vault dialog.
- Escape now closes the add-vault dialog from every page. Previously the built-in handler only fired when focus was inside an input, so Escape did nothing on the vault-type selection page.
- Deleting a custom field now sticks, and renaming a custom field no longer leaves a duplicate behind (upstream [#1342](https://github.com/buttercup/buttercup-desktop/issues/1342)). The fix is in `buttercup-core`: the Format B vault merge (run on every save) was discarding each property's deletion tombstone, so the next save resurrected any field that had been removed. Requires `codekunde/buttercup-core` at the commit carrying this change.
- The create/rename group dialog now focuses (and selects) the group-name field when it opens; the old focus effect keyed off a ref value and never re-ran once the dialog existed.
- Adding a new entry now focuses the Title field so you can type immediately, instead of leaving the form with nothing focused.
- The app now also registers and handles the legacy `buttercup://` URL scheme for inbound auth callbacks (all platforms), not just `codekunde-buttercup://`. Note: Google Drive sign-in still does not complete end to end, because the OAuth redirect it depends on (`buttercup.pw`) is an upstream service that is currently offline; a self-contained loopback auth flow is needed to fully restore it.
- Enabling browser access no longer crashes with an uncaught `EADDRINUSE` exception when the port is already taken (e.g. a second Buttercup instance). The failure is now reported as a notification and the preference is rolled back instead of showing as enabled while nothing is listening.
- An empty or truncated config/vault-list file no longer bricks the app on boot (upstream [#1107](https://github.com/buttercup/buttercup-desktop/issues/1107)). `FileStorage` was re-throwing the `JSON.parse` error, so a single corrupt file left the app unable to start with no way to recover short of editing files by hand. It now moves the bad file aside (renamed with a `.corrupt-<timestamp>` suffix) and starts from an empty store. Writes are also now atomic (written to a temp file and renamed into place), so a crash mid-write can no longer produce the truncated file in the first place.
- The vault's three-pane split (groups / entries / details) now remembers its column widths across restarts instead of resetting to the default every launch (upstream [#1367](https://github.com/buttercup/buttercup-desktop/issues/1367)). Sizes are stored per machine and applied proportionally, so the ratio holds at any window size.

## [2.29.0] - 2026-09-01

First release of the Codekunde fork. A modernization pass over the archived upstream 2.28.1: dependency security, Electron 44, and testing/CI tooling. No user-facing feature or behaviour changes.

### Security

- Cleared all 36 `npm audit` findings (4 critical, 16 high, 16 moderate) — audit now reports 0 vulnerabilities.
  - Removed `spectron` (end-of-life, unused), which pulled in vulnerable `webdriverio`, `puppeteer-core`, `got`, `extract-zip`, `@electron/get` and others.
  - Bumped `electron` 22 → 44, `electron-builder` 24 → 26 and `copy-webpack-plugin` 7 → 12.
  - Added `overrides` to force patched transitive dependencies: `xml2js`, `yaml`, `minimatch`, `pbkdf2`, `decode-uri-component`, `serialize-javascript`, `tar`, `uuid`.

### Changed

- Upgraded to Electron 44, and `@electron/remote` 2.0 → 2.1 (2.0.x crashed the
  renderer on Electron 44 with `isDesktopCapturerEnabled is not a function`,
  leaving a blank window). Adjusted `source/main` code for API/type changes:
  - `window-all-closed` handler no longer receives an `event` argument.
  - `LoginItemSettings.wasOpenedAsHidden` / `Settings.openAsHidden` are cast (no longer in Electron's type definitions; still present at runtime on macOS).
  - `clipboard.readText()` is now awaited in the auto-clear-clipboard timer.
- Replaced the Pug renderer template (`resources/renderer.pug`) with plain HTML (`resources/renderer.html`) and removed `pug` / `pug-loader`.
- The `buttercup` dependency now tracks the `codekunde/buttercup-core` fork.
- Pointed `repository`, `bugs`, `homepage` and the electron-builder `publish`
  target at `codekunde/buttercup-desktop`.
- Migrated the `build` config for electron-builder 26: `linux.desktop` entries moved under `desktop.entry`; `win.sign` / `win.publisherName` moved under `win.signtoolOptions`; `mac.notarize` is now a boolean (set to `false` — set it to `true` with `APPLE_TEAM_ID=9D8F4J769D` and the other Apple env vars to notarize).
- Dropped the Linux `armv7l` (32-bit ARM) AppImage target — Electron 44 no longer ships that architecture. Linux builds are now x64 + arm64.
- Removed the `afterAllArtifactBuild` hook (`resources/scripts/afterAllArtifactBuild.js`). It was a workaround for old electron-builder macOS zip/blockmap handling and broke under v26; v26 generates the mac `zip`, blockmap and `latest-mac.yml` natively.
- `resources/scripts/windowsSign.js` now skips signing (unsigned build) when `WIN_YUBIKEY_PIN` is unset instead of throwing, so `npm run package:win` works without the signing key.

### Added

- End-to-end UI tests with Playwright (`e2e/`, `playwright.config.ts`). Run with `npm run test:e2e` (or `npm run test:e2e:ui` for the interactive runner). See [`e2e/README.md`](e2e/README.md).
- `npm run start:isolated` — runs a development build against a throwaway data directory so it can coexist with a personally-installed Buttercup without touching its config, vault list or logs.
- CI: `.github/workflows/build.yml` builds unsigned installers for Windows, macOS and Linux on every push to `master` (and on `v*` tags, where it also drafts a GitHub release with the artifacts attached); can also be run manually. Rewrote `test.yml` (was pinned to deprecated actions and only ran on Ubuntu) into a 3-OS build/unit matrix plus a Playwright e2e job (the e2e job is informational — the Electron window doesn't reliably come up under a headless display; the suite passes on a real desktop).
- CI actions bumped to Node 24 runtime (`actions/checkout@v5`, `actions/setup-node@v5`, `actions/{upload,download}-artifact@v7`); CI Node is 22. `engines` bumped to `node >=20`, `npm >=9`.
